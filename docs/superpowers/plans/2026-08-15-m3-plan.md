# M3 Execution Plan — Streams

Date: 2026-08-15

**Goal:** the SDK becomes live: a consumer watches a real session's event stream as typed
events over `IAsyncEnumerable<T>` against `opencode2 serve`. Everything in this milestone
either serves that demo or rides the same runway (milestones are deliverable-first).
Sealed inputs: ADR-0008/0009/0010, research doc 02 (SSE: `IAsyncEnumerable`, no
auto-reconnect), doc 15 §5a/§6 (placement census), research log Sessions 22 (Q88) and 24
(Q92, #28/#32/#33 seals), the standing performance guardrails.

## Arc 2 — Location + merged-Request design session (seals before any body+query admission)

Census: 61 ops carry the optional `location` deepObject
(`location[directory]=…&location[workspace]=…`); all 15 body+query mixes are
location-only; `session.list` alone uses flat fields; ambient
`x-opencode-directory`/`x-opencode-workspace` headers are spec-invisible middleware;
server precedence query > header.

- [x] **Q-A, marshalling (sealed — Q93):** binder-owned per-property placement map — one
      uniform `{Op}Request` whose properties carry body/query/path placement in the
      operation plan; emitters stay name-blind; the body+query double-derivation refusal
      pin retires per-operation as the map admits it. Upstream parity: the first-party
      client emits one uniform `{Op}Input` per operation.
- [x] **Q-B, location rendering (sealed — Q94):** generated `Location` property on the
      request records (the spec-visible channel) plus an ambient default on
      `OpenCodeClientOptions` riding the header channel; an explicit per-request value
      wins by the server's own precedence — no client-side merge. `session.list`'s flat
      fields bind as ordinary query properties, no special case.
- [x] Session output: both seals recorded in the research log (Session 25); the stop
      condition ("no body+query operation admitted without the sealed merged-Request
      design") lifts.

## Arc 3 — SSE

Streaming endpoints **generate** like any other operation (Q96, ADR-0008 as corrected):
the engine is hand-written identity core, the endpoints are one-line delegations into it.
The arc splits because its two operations differ by an order of magnitude in closure —
`session.log` adds 58 schemas over a 2-branch union, `event.subscribe` adds 125 over an
87-branch one — and bringing an engine up should not be entangled with the larger union.

### Arc 3a — the engine, on `v2.session.log`

- [ ] Hand-written SSE engine beside the one-shot path: `ResponseHeadersRead` send reusing
      the pipeline's endpoint/auth/location decoration, status wall against the declared
      map, `text/event-stream` content-type wall, then a frame reader collaborator —
      CRLF normalization, `\n\n` boundaries, `data:` collection, a maximum-frame guard,
      cancellation and disposal. It never reuses the one-shot buffer, so the Arc 6 perf
      pass touches this shape once.
- [ ] Generator walls, each fail-closed: admit `text/event-stream` responses; recognize the
      `{id, event, data}` frame profile structurally and refuse anything else; bind the
      **JsonString dialect** (`contentSchema` + `contentMediaType`) so `data` types into
      its payload; emit `IAsyncEnumerable<T>` instead of a response envelope, with no
      per-call options parameter (Q97, ADR-0007).
- [ ] Declare and pin `Microsoft.Bcl.AsyncInterfaces` directly before the first stream
      operation goes public: it is what supplies `IAsyncEnumerable<T>` on `netstandard2.0`
      and `net472`, and it currently arrives only as a `System.Text.Json` transitive
      (ROADMAP known gap).
- [ ] `after`/`follow` bind as ordinary query parameters. The SDK performs no automatic
      resume — `after` is the consumer's to pass, and the SSE `id:` line is not a resume
      token (the first-party reader discards it). This seals the ROADMAP open question.
- [ ] Mid-stream Effect failure causes (`x-effect-stream.causeSchema`) surface as a typed
      transport failure rather than being yielded as if they were events.
- [ ] **Demo:** follow a real session's durable log live against `opencode2 serve`.

### Arc 3b — `v2.event.subscribe`

- [ ] Pure breadth over the proven engine: the global bus, no parameters, no resume.
      Admits the 87-branch `V2Event` union and its 125 new schemas; unknown variants ride
      the ADR-0009 carriers.
- [ ] **Demo:** watch the live global event stream.

## Arc 6 — The deliberate performance pass (#23-anchored, last on the runway)

- [ ] One pass, after the SSE buffering shape exists (earlier is double work): P1
      single-pass union dispatch (reader-based known-tag path; DOM kept for unknown
      carriers), P3/V28 success-path UTF-8/stream adapters (ADR-0007 `RawBody` stays on
      the error path), V29 internal-handoff copy elision (ADR-0004 defensive copy stays
      for consumers), the cursor-list re-copy. Closes #23 and #29.
- [ ] #33 executes inside the converter rewrite as sealed: carrier constructors refuse
      tag/payload disagreement; `Write` stays payload-only verbatim replay.
- [ ] All under `MemoryDiagnoser`, allocation-first, before/after numbers in the PR.
      Interim discipline: the baselines must not regress through earlier arcs —
      `GetMessageAsync` 49.5 μs / 25.92 KB, `ListMessagesAsync` 55.7 μs / 26.67 KB,
      `GetHealthAsync` 1.5 μs / 2.08 KB, `DeserializeDeepAssistantMessage` 45.4 μs /
      17.37 KB, and the frame reader 321.45 KB over 64 frames (its time reading is noisy;
      allocation is the stable figure). These restate the earlier numbers against a
      wire-shaped payload rather than an indented one.

## Boundaries and stop conditions

The standing list carries: opencode-dialect-only, fail-closed on unsupported shapes,
name-blind emitters, no body+query admission before Arc 2 seals, Extensions dependencies
inside research doc 06's policy, no stream design bypassing this plan, no SDK hot-path
optimization outside Arc 6, and no performance claim without benchmark numbers. New under
ADR-0010: no transport-injection or composition-seam surface returns without the ADR's
reversal trigger.

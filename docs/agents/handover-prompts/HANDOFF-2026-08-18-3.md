## Immediate Bounded Task - CI Analyzer and Formatting Gate

This is an evidence/decision task before #49, not permission to optimize by weakening assurance.

### Current mechanical facts

- `dotnet build --configuration Release` runs with `RunAnalyzersDuringBuild=true`,
  `EnforceCodeStyleInBuild=true`, `AnalysisMode=All`, warnings-as-errors, and `IDE0055=error`.
- The Linux workflow then runs `dotnet format --verify-no-changes --no-restore` over the same
  solution. `--no-restore` skips restore only; `dotnet format` has no `--no-build` option.
- Tests already use `dotnet test --configuration Release --no-build`; that is why the test step does
  not repeat compilation or analyzer work.
- `OpenCode.slnx` contains 8 projects. On Linux their target declarations produce 20 target
  compilations: two five-TFM product libraries, two three-TFM test projects, and four single-TFM
  projects. The repository has 617 non-external C# files excluding `bin/` and `obj/`.
- NuGet packages are already cached per OS. That cache avoids package downloads, not Roslyn
  compilation or analyzer execution.

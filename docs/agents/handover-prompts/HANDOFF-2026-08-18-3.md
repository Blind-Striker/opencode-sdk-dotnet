## Immediate Bounded Task - CI Analyzer and Formatting Gate

This is an evidence/decision task before #49, not permission to optimize by weakening assurance.

The accepted policy gives each concern an explicit owner:

- build owns compiler, SDK CA, third-party analyzer, source-generator, and build-enforceable IDE
  diagnostics;
- `dotnet format whitespace` owns physical encoding/EOL/final-newline/trailing-whitespace and syntax
  formatting; and
- unfiltered `dotnet format style --severity warn` owns import organization plus every configured
  warning/error Roslyn style rule, including rules unavailable during build.

No diagnostic ID allow-list is maintained. Existing style errors remain errors. Repository
generation is a separate mutating path and keeps its project-scoped full formatter over only
generator-owned paths.

### Current mechanical facts

- `dotnet build --configuration Release` runs with `RunAnalyzersDuringBuild=true`,
  `EnforceCodeStyleInBuild=true`, `AnalysisMode=All`, warnings-as-errors, and `IDE0055=error`.
- The Linux workflow runs separate `dotnet format whitespace` and unfiltered warning-level
  `dotnet format style` gates over the solution. The later generation-verification step writes its
  candidate output and runs project-scoped full format over only generated paths before comparing
  snapshots. `--no-restore` skips restore only; `dotnet format` has no `--no-build` option.
- Tests already use `dotnet test --configuration Release --no-build`; that is why the test step does
  not repeat compilation or analyzer work.
- `OpenCode.slnx` contains 8 projects. On Linux their target declarations produce 20 target
  compilations: two five-TFM product libraries, two three-TFM test projects, and four single-TFM
  projects. The repository has 617 non-external C# files excluding `bin/` and `obj/`.
- NuGet packages are already cached per OS. That cache avoids package downloads, not Roslyn
  compilation or analyzer execution.

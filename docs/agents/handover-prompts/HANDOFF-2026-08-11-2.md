## How we got here — read this before anything else

The project ran a heavy research/design runway first (research log sessions 1–14): three
design specs, ADRs 0001–0009, and a 12-slice implementation map, all sealed through
repeated grill sessions. Slice 0 (tooling skeleton) landed fine. **Slice 1 (ingestion)
then produced 8.6K lines with zero SDK output** — a semantic projection buried under
DOM-surveillance machinery (reflection member whitelists over every reader type, planned
document-wide hashes, DOM inventories, SpecIR snapshots) plus a 1.5K-line test DSL, all
before any generator, model, or client existed.

A mid-execution **complexity checkpoint** (research doc 13) ran two probes that decided
everything after it: (1) the production projection **absorbs the complete pin** — 188
operations, 472 named schemas, all landmarks, deterministically — so the semantic core is
right; (2) raw **Kiota loses this dialect's wire data** (drops `type` markers, loses whole
union payloads, silences unknown tags, no typed error bodies) — so the own-generator
decision is right. The failure was therefore not architecture but process, and the
maintainer sealed a course correction (research log **session 15**, Q63–Q65):

- **Cause 1:** fail-closed maximalism was transplanted from the analyzer wall (cheap
  there) onto the reader DOM, where a whitelist's cost scales with the *library's*
  surface, not with product risk.
- **Cause 2:** the slice map was a layer cake in vertical clothing — first callable
  client at slice 5, first real request at slice 7; feedback arrived after maximal
  investment.
- **Cause 3:** paper grill sessions ratchet monotonically (every risk gains a mechanism;
  nothing answers "what does this cost in code?"), and assurance intensity was never
  scaled by blast radius.

The Slice 1 branch was then **closed lean in the same session**: surveillance machinery
deleted (−851/+131), semantic-loss checks folded into projectors, `ISpecIngestion`
orchestration + `$ref`-sibling raw scan + dangling-ref sweep added, tripwire/boundary/
landmark tests written, docs regime changed. PR #14 (squash) closed issue #2.

## What is true now (the standing rules)

- **Sealed surface = ADRs + `AGENTS.md` only.** The specs under `docs/superpowers/` are
  vision/reference (bannered): direction and rationale, not law. Contradicting one is a
  level-0 note; the deviation protocol's level 2 covers canonical docs only.
- **Red lines (maintainer):** the analyzer wall + TWAE stays exactly as is; the
  Testably/`IFileSystem` seam with the TestableIO enforcement analyzer stays;
  `Microsoft.OpenApi` (pinned 3.9.0) stays the reader.
- **Drift radar:** git diffs of committed generated output + the test suites are primary;
  targeted validators exist only at known lossy seams (unrecognized raw keywords,
  `prefixItems` tripwire, `$ref` siblings, dangling refs, boundary guards, landmark
  smoke). No DOM inventories, no SpecIR snapshots, no speculative hashes.
- **Consumer-pull:** every SpecIR fact, mechanism, option, and test names a consumer or a
  concrete failure it prevents. A fact needed by a later feature is added *in* that
  feature.
- **Blast-radius assurance** (`AGENTS.md`): shipped SDK runtime highest; committed
  generated output next; repo tooling internals lightest.
- **Delivery model:** `docs/ROADMAP.md` carries six milestones (M1 walking skeleton → M6
  operational closure). Each milestone gets a **1–2 page** plan written when it starts.
  The slice map and per-slice issue chain are retired; issues #3–#12 need re-triage
  against the milestone model (maintainer's call — do not bulk-close on your own).
- Test authorship: builders/scenarios exist under `tests/OpenCode.Sdk.Tools.Tests/Support/`
  — use them, **grow them only when a test pulls a new verb**. Named scenario classes only
  on the promotion rule. No count assertions against the pin.

## The task: M1 — walking skeleton

**Sealed deliverable:** `v2.health.get` + `v2.session.message` end to end — SpecDocument →
Binder → EmitPlan → Roslyn emitters → committed source under `src/OpenCode.Sdk` → minimal
transport core → callable client — **demonstrated once by hand against a real
`opencode serve`**, output pasted into the PR. Deliberately process-free: no launcher, no
test harness, no CI integration legs, no coverage gate. Two independently mergeable arcs:

- **Arc A — compiler + committed models:** two-operation selection profile (a checked-in
  text file under `tools/`), sparse curation v0 with selection-scoped coverage checks,
  Binder → EmitPlan, model/union/registry emitters for the selected reachable closure,
  Writer (output manifest, stale cleanup, `dotnet format` post-step), real `generate` +
  `--verify`; the committed models compile on all five TFMs.
- **Arc B — callable client:** exception/response/request-option spines,
  `Pipeline.ExecuteAsync` behavior core (endpoint + BYO HttpClient construction, basic
  auth chain, directory header, User-Agent, cancellation — **no** retry/telemetry/hooks/
  DI-extensions yet), envelope/routes/client emitters, the two generated methods, level-2
  contract tests for both operations and their declared errors, the manual demo.

**First step of the session: write the M1 plan (1–2 pages), get the maintainer's OK, then
execute.** The walking-skeleton spec
(`docs/superpowers/specs/2026-08-11-production-walking-skeleton-design.md`) is the design
reference — take its decisions (operation selection semantics, semantic-risk policy, the
`SessionMessage` converter contract, error mapping table, stop conditions), not its
ceremony; its verification matrices are a menu, not a checklist. Keep the partial-breadth
guard to the cheapest mechanical form that actually blocks `dotnet pack`.

`v2.session.message` is chosen because its closure exercises the hard path: bound session
handle, two path parameters, `{data}` envelope, an 8-variant marked union whose assistant
branch nests a 3-variant content union and a 4-state tool-state union, declared
400/401/404 errors (404 dedups to two not-found variants). Its unions are all *marked* —
if the closure unexpectedly pulls in a structural union, that is the deferred emission
decision surfacing early: stop and take it to the maintainer as an API review.

## Warnings

- **Do not resurrect the deleted machinery** — reflection member whitelists, DOM
  member/default inventories, SpecIR-of-the-pin snapshots, document-wide raw hashes,
  fatal unknown `x-*`, per-keyword refusal tests. Session 15 records why each died. A new
  assurance mechanism needs a consumer or a demonstrated failure, in writing.
- Typed annotation/validation members (`title`, `default`, `readOnly`, bounds…) are
  **silently ignored** by design; unrecognized *raw* keywords still refuse (nothing
  downstream can ever see them). Don't "fix" either direction.
- The landmark smoke is the refresh gate: a red landmark is evidence about the wire —
  stop and classify, never patch the assertion.
- Plans stay 1–2 pages; per-task commits on the arc branch are the agreed loop; master
  merges via PR with maintainer approval; squash-merge is the house style since PR #14.
- Never modify the evidence worktree or its branch.
- The maintainer works in Turkish conversation, English artifacts; align on structure
  before writing documents; canonical-doc edits need explicit per-edit approval.

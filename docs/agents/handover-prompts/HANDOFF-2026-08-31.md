## Standing facts and gotchas

- **Run the gates with a unique TRX name.** Three unnamed one-off full-suite failures happened
  across this arc under implementer gates (3/4,139, 1/4,242, 3/4,406); none reproduced and no runner
  ever named a test, in one case because the report was overwritten before it was read. Use
  `dotnet test … -- --report-trx --report-trx-filename <unique>` so a recurrence yields names.
  Candidates to exonerate first: `ClientTerminalWebSocketTests.cs:44` and
  `LoopbackPortReservationTests.cs`.
- **Implementers must be told explicitly never to background a `dotnet` command.** One did on Task 1
  and stalled until nudged. Foreground, generous timeout, every time.
- **A new family folder needs the `.editorconfig` IDE0130 globs extended before `generate`** (see
  Findings; precedent `ff8f527`).
- **The `opencode-pty` daemon does not exist on Windows.** `@opencode-ai/pty` ships darwin/linux
  platform packages only at the pin. Any local persistentPty result on this workstation is the
  daemon-absent arm — correct, asserted, and only half the story.
- **The WSL2 recipe lives in `tests/OpenCode.Sdk.Sandbox/README.md`.** Its four gotchas: drive WSL
  from a script file (`MSYS_NO_PATHCONV=1 wsl.exe -- bash /mnt/c/<path>.sh`), because Git Bash
  mangles quoting and converts `/tmp` paths; stop the server by pattern
  (`pkill -f "index.ts serve --port 4097"`), because a backgrounded `setsid nohup … &` leaves the
  pid file empty; **never share the Windows checkout's `node_modules` with WSL** — one tree holds
  the platform package of whichever OS installed last; and the sandbox needs `--no-launch-profile`
  while its earlier session legs answer 500 on a provider-less isolated server, so it is not a
  substitute for the live test.
- **The maintainer's Linux-side assets persist:** the WSL clone at `~/repos/opencode-sdk-dotnet` and
  bun 1.3.14 at `~/.bun`. Reuse them rather than re-cloning. **That clone's superproject is at
  `2801dd4` and its submodule at `106629aa`**, so a bare `git submodule update` there would
  re-check-out `106629aa`: after this work is pushed, `git pull` in the WSL clone **first**, then
  `git submodule update` (the shallow submodule fetches the missing commit itself).
- **TUnit captures console output.** Any evidence a test prints lives in the TRX or the TUnit report
  artifact, never in the CI step log. Fetch the artifact.
- **Slopwatch walks the filesystem, does NOT consult `.gitignore`, and is blind inside a git
  worktree.** Run it from this main checkout with the canonical invocation
  (`--exclude ".scratchpad/**,external/**"`, `quality-gates.md`) — CI and local must use the same
  line, or drift appears only on the hosted runner.
- **No suppression without an explicit maintainer approval AND a good, verifiable reason.**
  Slopwatch is at zero and stays there; a documented impossibility argument is the only accepted
  shape (`abdfb28` is the precedent). This rule is not in canon yet — see Release-prep decisions.
- **`external/` is a submodule, deliberately checked out on CI** (`submodules: true`) so `bun
  install` can build the pinned server. It is read-only evidence: never edit it, never move its
  checkout. Use `git -C external/opencode …` rather than `cd`, because the Bash tool's working
  directory persists across calls.
- **Never edit the performance project while a benchmark run is live,** and keep the machine quiet.
  **The canonical benchmark invocation is in `quality-gates.md`**; `--runtimes net10.0 net472` is
  load-bearing, because without it BDN labels every case `DefaultJob` and the comparison joins on
  the runtime label.
- **Timing on this workstation is not comparable across runs.** Allocation is the reliable axis;
  never quote a cross-run timing delta from here.
- **Editor/LSP diagnostics in this repo are stale and noisy** — routinely flagging generated members
  that exist. The gate is the referee, never the squiggles.
- **No backward compatibility until release** (Q131): renames are free; curation reasons must state
  facts that are true *today*, and several have gone stale as later work landed — check before
  citing one.
- Naming traps: the location query member is `workspace` (bodies elsewhere use `workspaceID`); the
  emitted vcs method is `GetBranchesAsync`, not `ListBranchesAsync`; `OperationNamePolicy` falls
  back to the HTTP method as the verb, so `worktree.refresh` and `persistentPty.handoff` carry a
  mechanical `Post` infix in their generated names. Check what the emitter actually named a member
  before writing a test against it.

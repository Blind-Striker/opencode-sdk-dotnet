## Measurement findings the next session should not re-derive

Full report: <https://claude.ai/code/artifact/c523b445-3e6a-4dea-a46a-97f5dd3e5231>

- **Timing on this workstation is not comparable across runs.** A control run of *identical*
  compiled code four hours apart returned byte-identical allocation on 96 of 96 cases while 87 of
  those same cases moved more than 10% on time (0.12× to 1.36×). Never draw a timing conclusion
  from two separate runs here; allocation is the reliable axis.
- **Allocation, baseline → now:** .NET 10.0 **−1,847,984 B** (48 improved / 21 same / 7 worse by
  ≤64 B); net472 **+56,615 B** (47 regressed), of which `MessageList` is 50,242 B, mostly the
  `page-480` fixture at ~33 B per item. **Unattributed** — a bisect across the spec refresh and the
  envelope arc is the named follow-up. Wire bytes were identical on all 76 matched cases per leg,
  so the comparison is like-for-like.
- **Allocation amplification is scale-invariant at ~5.8×** (2 KB, 54 KB, and 1 MB fixtures all sit
  there), and the transport is exonerated: `ExecuteWithoutAdapterAsync` allocates a flat 2,128 B
  across a 490× payload range. The whole factor belongs to deserialization.
- **A second cost class is fixed per-call buffers**, invisible on large payloads and brutal on
  small: `PtySession.ReadFramesAsync` 932× (16,776 B for an 18-byte frame — a per-call 16 KiB
  receive buffer), the SSE reader ~26 KB per stream open, `SessionActive.GetActiveAsync` 53× at one
  entry. The PtySession `ArrayPool` rent is the cheapest targeted win and already has its own rung.
  **That ladder now needs a rerun before it is acted on:** the shared terminal socket core added one
  interface dispatch per frame on the same path.

## Standing facts and gotchas

- **The `opencode-pty` daemon does not exist on Windows.** `@opencode-ai/pty` ships darwin/linux
  platform packages only at the pin, the server spawns it as a detached child over a Unix domain
  socket, and no container can host it alone. Any local persistentPty result on this workstation is
  the daemon-absent arm — correct, asserted, and only half the story.
- **Slopwatch walks the filesystem and does NOT consult `.gitignore`.** `node_modules/` is
  gitignored and was still scanned on CI. The canonical invocation
  (`--exclude ".scratchpad/**,external/**"`, `quality-gates.md`) is what protects the gate — CI and
  local must use the same line, or drift appears only on the hosted runner.
- **`external/` is a submodule, deliberately checked out on CI** (`submodules: true`) so `bun
  install` can build the pinned server. It is not ignored, and the runner creates its
  `node_modules` itself.
- **Never edit the performance project while a benchmark run is live.** BDN regenerates and
  rebuilds a project referencing it per job/runtime *during* the run; a mid-edit tree either breaks
  a later build or silently changes what is measured. Run from a clean copy, or leave the tree
  alone; keep the machine otherwise quiet.
- **The canonical benchmark invocation is now in `quality-gates.md`.** `--runtimes net10.0 net472`
  is load-bearing: without it BDN labels every case `DefaultJob`, and the comparison joins on the
  runtime label, so a whole run becomes unjoinable against the archive. (This cost a 1h48m run; the
  tool now fails loudly instead of printing an all-one-sided comparison.)
- **Editor/LSP diagnostics in this repo are stale and noisy** — routinely flagging generated members
  that exist. The gate is the referee, never the squiggles.
- **No backward compatibility until release** (Q131): renames are free; curation reasons must state
  facts that are true *today*, and several have gone stale as later work landed — check before
  citing one.
- Naming traps: the location query member is `workspace` (the body elsewhere uses `workspaceID`);
  the emitted vcs method is `GetBranchesAsync`, not `ListBranchesAsync`.
- `session.idle` is deprecated upstream with no publisher while `SessionIdle` stays in the event
  union — an upstream-report candidate parked with the other reports, which this arc added three
  more to (research log Q156).

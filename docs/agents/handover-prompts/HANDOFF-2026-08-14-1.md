## Session Mechanics The Docs Don't Carry

- **Dev loop:** the maintainer authorizes committing per green increment and pushing
  within the loop; red-test-first is demanded; public-API taste decisions are batched to
  the maintainer as options with a recommendation (they often counter-question, then
  seal). Run all six gates before every commit, chained with `set -o pipefail` and an
  explicit ALL-GREEN marker. Do not use `grep -c` inside the chain — it exits 1 on zero
  matches and reads as a red gate.
- **Regen ritual:** edit emitters → `dotnet run --file tools/opencode-tool.cs -- generate`
  → review the git diff of committed output → run tests. Emitter changes turn the three
  Verify snapshot tests in `OpenCode.Sdk.Tools.Tests/Snapshots/` red; review the received
  diff, then accept received→verified. `generate --verify` must be a byte-identical no-op
  before commit.
- **Public API baseline** (`PublicApi.verified.txt`, TFM-shared) will change in M2 — new
  public surface is expected; the baseline diff is itself review surface for the
  maintainer, never auto-accepted silently.
- **Perf discipline:** perf-touching changes carry before/after BenchmarkDotNet numbers
  (`tests/OpenCode.Sdk.Performance.Tests`, `MemoryDiagnoser`); allocation deltas are the
  primary regression currency (deterministic), timing secondary. Benchmarks are not a CI
  gate. Task 7 adds a `ListMessagesAsync` benchmark once the surface exists.
- **Multi-TFM traps already paid for** (do not rediscover): downlevel legs need
  conditional `<Using>`/`<Reference Include="System.Net.Http">` items (test csproj has
  them since `52a5e3b`); ns2.0's BCL lacks `[NotNullWhen(false)]`, so generated
  non-null-proving guards carry an explicit `x is null ||` disjunct (see the union marker
  guard); SonarAnalyzer relaxes test rules only on test-framework references, so
  benchmark-style projects arbitrate via csproj `NoWarn` + a single-line
  `slopwatch-ignore: SW005` comment; the net472 test leg builds only on Windows CI but
  compile-probes locally via `-p:TargetFrameworks=net472`.
- **External review pattern:** the maintainer runs reviews outside this harness from
  hand-off instruction files (gitignored `.scratchpad/ultra-review-handoff.md` +
  `VERIFY-HANDOFF.md` from the M1 cycle — reusable templates with the commit range and a
  JSON result contract). Findings come back as scratchpad reports; triage verifies before
  trusting, then everything surviving is preserved into GitHub issues (nothing lives only
  in scratchpad).

## Task 1 — Uniform `*Request` rename (Q83)

Every operation input is `{Group}{Subject}{Verb}Request`; the Options family retires.

- **Hand-written spine:** `ListOptions.cs` → `ListRequest.cs` (abstract record
  `ListRequest`, same Limit/Order/Cursor trio — the M3 paginator seam keeps its shape
  under the new name). `ListOrder`, `ListCursor`, `SessionParentFilter` unchanged.
- **Generator:** `OperationNamePolicy.OptionsTypeName` retires; query records derive
  through `RequestTypeName`. **Deliberate consequence:** an operation declaring both a
  body and query parameters derives the same type name twice and fails the existing
  collision wall — that is the intended fail-closed state until a merged-Request design
  (one Request carrying both, AWS-marshalling style) is sealed. Record that in the wall's
  refusal test.
- **Internal plan/emitter vocabulary** (`OperationOptionsPlan`, `OptionsPropertyPlan`,
  `OptionsEmitter`, `OperationPlan.Options`, `QueryValueKind` stays) may rename to
  `Query*`/`*Request*` for coherence — internal taste; pick one scheme, be consistent.
- **Signatures:** method and route-builder parameter `options` → `request`
  (`ListSessionsAsync(SessionListRequest? request = null, OpenCodeRequestOptions?
  requestOptions = null, …)`); `requestOptions` unchanged. Update
  `ReservedParameterNames` to the emitted reality (`request`, `requestOptions`,
  `cancellationToken`, `pipeline`) — `options` leaves the set.
- **Fallout to update in the same sweep:** regen (SessionListOptions→SessionListRequest,
  MessageListOptions→MessageListRequest), all eight emitter snapshots re-verify, the
  PublicApi baseline (rename-only diff — review it as such), contract tests, the
  `ListMessagesAsync` benchmark, the sandbox program, ROADMAP wording ("`ListOptions`
  seam" → `ListRequest`). The research log stays untouched (dated history).

## Task 2 — Feature-slice layout migration (Q84)

Target tree (namespaces stay `OpenCode.Sdk` / `OpenCode.Sdk.Models` — folders are
placement, not naming):

```
src/OpenCode.Sdk/
  OpenCodeClient.cs  OpenCodeClientOptions.cs  OpenCodeRequestOptions.cs
  OpenCodeResponse.cs  OpenCodeException.cs  OpenCodeApiException.cs
  OpenCodeTransportException.cs  ErrorBehavior.cs  OpenCodeRoutes.cs
  Pagination/  ListRequest.cs  ListOrder.cs  ListCursor.cs
  Sessions/    SessionsClient.cs  SessionClient.cs  SessionParentFilter.cs
               SessionListRequest.cs  MessageListRequest.cs  Session*Response.cs
               MessageListResponse.cs  SessionMessageResponse.cs
  Health/      HealthResponse.cs
  Models/      (unchanged)
  Internal/    (unchanged)
```

- **IDE0130 arbitration:** flat public namespaces over feature folders trip
  folder-matches-namespace. Arbitrate per the standing pattern (`.editorconfig` §12
  comment naming the winner), scoped to `src/OpenCode.Sdk` — do not relax the rule for
  tools or tests.
- **Emitters:** `GeneratedSource.RelativePath` gains the feature folder. The mapping is
  mechanical and name-blind: family files (clients, envelopes, request records) go under
  `{RouteContainerName}/`; the root client, `OpenCodeRoutes`, and the registry keep their
  current homes. Hand-written files move with `git mv`.
- **Writer allowlist** (`GenerationWriter` source-path check) must learn the family
  folders — extend it fail-closed (derive admitted folders from the plan's container
  names rather than an open glob). Manifest paths churn once; stale-source deletion
  removes the old paths in the same regen.
- **Tests mirror:** reorganize `OpenCode.Sdk.Tests` folders to mirror the new tree
  (contract tests under `Sessions/`, spine tests under `Pagination/` etc.); test
  namespaces stay flat, same arbitration. `Tools.Tests` already mirrors `tools/`.

## Task 3 — Extensions bring-up (Q85)

`src/OpenCode.Sdk.Extensions` is an empty shell today.

- **Scope:** `AddOpenCode` overloads mirroring the three client constructors
  (`(Uri)`, `(Uri, Action<OpenCodeClientOptions>?)`, BYO-`HttpClient`), registering the
  root `OpenCodeClient` plus sub-client registrations
  (`services.AddSingleton(sp => sp.GetRequiredService<OpenCodeClient>().Sessions)`) so a
  consumer resolves `SessionsClient` directly. Root ownership/dispose stays with the
  container's singleton root.
- **Hand-written first:** one client family exists; generator-emitted registrations
  become worthwhile when families multiply — leave a research-log note, not code.
- **Dependency policy:** research doc 06 governs what the Extensions package may
  reference — read it before adding `Microsoft.Extensions.*` packages, and check whether
  `IHttpClientFactory` integration is in or out of the first cut (recommendation: out;
  additive later).
- **Tests:** a new `OpenCode.Sdk.Extensions.Tests` project (mirroring layout, TFMs per
  the Extensions csproj); cover each overload's composition and the sub-client
  resolution path.

## Session Mechanics The Docs Don't Carry

- Dev loop: all six gates before every commit, chained under `set -o pipefail` with an
  explicit ALL-GREEN marker; commit per green increment; push on the working branch is
  authorized; red-test-first is demanded.
- **Decisions to the maintainer go as plain text in chat — never AskUserQuestion
  dialogs** (option-dialog annotations have been lost in transit before; the maintainer
  rejected the flow). Batch them with a recommendation; they often counter-question,
  then seal.
- Regen ritual: edit emitters → `dotnet run --file tools/opencode-tool.cs -- generate` →
  review the git diff of committed output → snapshot received→verified after review →
  `generate --verify` must be a byte-identical no-op before commit.
- The PublicApi baseline diff is maintainer review surface — for this batch it should be
  renames and (for Extensions) a new assembly baseline only; anything else is a defect.
- Perf: the rename is perf-neutral; do not re-run benchmarks for it. Extensions adds no
  hot path.

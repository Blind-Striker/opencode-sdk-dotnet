Task 0 changes an incoming agent must know before touching the generator:

- **Ingestion-wall admits** (each fail-closed to the observed population, all red-tested):
  a single-element validation-only `allOf` wrapper unwraps into its host
  (`SchemaShapeClassifier.IsValidationOnlyAllOfWrapper`); a single-value number/integer enum
  projects as `LiteralKind.Number`; a bare `{"type":"array"}` projects as array-of-any-value;
  `prefixItems` admits exactly two shapes in `PrefixItemsAdapter` — the closed tuple
  (`minItems == maxItems == arity`, no `items`) and Effect's NonEmptyArray encoding (single
  prefix element sharing the `items` `$ref` target → plain `ArrayNode`); the old
  location-pinned admission is retired, shape validation replaced it.
- **Union machinery for the v2 topology** (`SchemaPlanBinder`, `UnionNormalizer`,
  `UnionEmitter`, `ModelEmitter`): the discriminating marker is *selected* (first property, in
  the first branch's document order, that every branch carries with one kind and pairwise
  distinct values — `status` beats the duplicated `type` on the Compaction family); a union
  branch may be a **nested marked union** (exactly one level): `SessionMessageCompaction :
  SessionMessageInfo` carries `BaseTypeName` + `FixedMarker` (`type=compaction`) on its
  `UnionPlan`, its variants override both chain markers, its unknown carrier fixes the outer
  tag; promoted inline branches are named root + marker value (`PromptFileSourceInline`/`Uri`);
  the special-number rule accepts v2's one-level-nested encoding.
- **Two serialization bugs were caught by the new nested-union tests and fixed in the
  emitter** — unknown-carrier marker overrides now emit `[JsonPropertyName]` (STJ otherwise
  fails constructor binding), and a union converter's `Write` serializes a nested-union
  variant through its **declared base type's** typed context property so the nested
  converter's raw-payload path runs (runtime-type metadata would serialize the carrier as an
  ordinary record). Both behaviors are covered by `OpenCode.Sdk.Tests` serialization tests.
- **Single surface**: `SpecSurface` is deleted; `OperationIdentityParser` refuses any
  operationId without the `v2.` prefix (located error); `GenerationReport` carries one
  `PendingOperationIds`; the `.generation-incomplete` marker and the CLI print one "Pending
  operations" count. The word "legacy" does not exist in production code.
- **Writer semantics** (`GenerationWriter`): manifest-diff cleanup — files in the previous
  manifest but absent from the new plan are deleted; the writer touches nothing outside the
  manifest and its admitted subtrees (`Models/`, `Internal/Serialization/`). Task 3 broadens
  ownership and must add the unmanifested-overwrite refusal and provenance-header checks.

## Remaining Work (Arc B Tasks 1–4)

The plan document is canonical; this is the operational detail on top of it.

### Task 1 remainder — operation binding

- `handleParameter` joins `GroupCuration` (`[JsonPropertyName("handleParameter")]`).
  Validation: root placement rejects client/handle fields; client placement requires
  `clientName`; `handleName` and `handleParameter` are paired; the handle parameter names a
  required path parameter on at least one selected operation in that group; curation-to-spec
  orphan checks stay global; selection-scoped coverage during staged generation.
- Consumed-only plan types (`ClientPlan`, `OperationPlan`, `OperationParameterPlan`,
  `EnvelopePlan`, `ErrorMapPlan`) + `OperationPlanBinder`. Known seam: `SchemaPlanBinder`
  still resolves type names internally (`TypePlanBinder` is a private nested class;
  `SchemaBindingResult` discards the name map). Resolve names once per `SpecBinder.Bind`, pass
  the same map to schema and operation binding; do not let operation binding reinterpret
  schemas or read raw OpenAPI.
- Bind only ordinary GET + JSON + path-parameter operations with one 200 success, no
  body/query/stream/wildcard. Handle-declared groups put the handle parameter on the handle;
  everything else stays flat. Add an operation/protocol binding error category — do not
  mislabel route/status/media failures as schema errors.
- Tests: complete pinned plans, handle-versus-method parameters, collisions, documentation,
  status maps, batched failures, determinism; a synthetic same-shape operation with different
  names binds without new production branches; an operation in a group without a handle
  declaration stays flat even when it carries `sessionID`.
- Blueprint (recommended, consumed-only): expected final values `OpenCodeClient.GetHealthAsync`
  → `HealthResponse` / `HealthResponseAdapter`; `SessionClient.GetMessageAsync` →
  `SessionMessageResponse` / `SessionMessageResponseAdapter`. Route members enter the API
  baseline — settle their shape before emission (reference shape: nested
  `OpenCodeRoutes.Health.Get`, `OpenCodeRoutes.Sessions.GetMessage(sessionId, messageId)`;
  nested public classes trip CA1034 — use the narrow arbitration pattern, never a global
  weakening).

### Task 2 — hand-written HTTP core

Identity files per the plan (options/response/exception spine, `IEnvironmentProvider`,
`Pipeline`, `ResponseAdapter`, `SystemEnvironmentProvider`, friend metadata). Locked
decisions that survive the retarget verbatim: URI constructors own endpoint authority; BYO
`HttpClient` requires `options.Endpoint`; never touch `BaseAddress`/`DefaultRequestHeaders`;
absolute HTTP(S) endpoints without query/fragment, normalized path prefix preserved; owned
client disposed, injected never; root disposal marks wrappers unusable; single send primitive
`SendAsync(request, ResponseHeadersRead, ct)`; Basic auth user `opencode`, explicit password
before one-time `OPENCODE_SERVER_PASSWORD` fallback; per-request decoration, never shared
headers; `OpenCode.Sdk/<informational-version>` User-Agent (the safe informational-version
extraction still needs an explicit decision + tests — do not silently substitute assembly
version). **Changed by the retarget:** there is no `x-opencode-directory` header — per-request
scoping rides the v2 `location[...]` query convention, bound as operation parameters (neither
selected M1 operation takes one, so M1 ships no directory affordance at all).
Error channels: throw by default; `OpenCodeRequestOptions.NoThrow` per call suppresses only
API-status exceptions; unknown tag / undeclared status / known tag at wrong status →
`UnknownOpenCodeError` with exact tag and raw `JsonElement`; malformed non-2xx JSON → null
typed error + exact raw body; unexpected/malformed 2xx → `OpenCodeTransportException`;
`OperationCanceledException` always passes through. Pipeline signature:
`Task<TResponse> ExecuteAsync<TResponse>(HttpMethod, string route, ResponseAdapter<TResponse>,
OpenCodeRequestOptions?, CancellationToken) where TResponse : OpenCodeResponse` — buffer the
JSON body, synchronous adapter maps `(status, rawBody)`, pipeline applies throw-vs-NoThrow
after adaptation.

## Stop Conditions

Stop and involve the maintainer if: the Binder needs Microsoft.OpenApi or raw JSON for a fact
SpecIR claims to provide; an emitter needs an operation ID, wire group, or concrete
client-name branch; a selected shape exceeds the declared M1 capability rather than failing
closed; a **structural** union enters the selected closure (nested *marked* unions are now
supported — one level only); generated ownership cannot distinguish hand-written files; a
temporary public or transport API becomes necessary; any locked TFM fails to compile; partial
generation packs successfully; or retry/telemetry/DI/launcher/SSE/breadth becomes necessary
merely to call the two M1 operations.

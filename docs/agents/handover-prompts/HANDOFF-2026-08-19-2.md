## Exact Next Increment - #53 Typed-Cause M3 Subset

Issue title: **M3/M5: close ingestion walls for typed schema and OpenAPI host semantics**.

The issue body inventories seven wall families. Do not execute that whole inventory now. The sole

### Current pinned cause contract

Both `v2.session.log` and deferred `v2.event.subscribe` declare the same extension:

- `encoding`: `sse`;
- `failureEvent`: `effect/httpapi/stream/failure`;
- `causeSchema`: an array whose items are a tagged `Fail | Die | Interrupt` union;
- `Fail.error`: `not: {}`;
- `Die.defect`: unrestricted `{}`;
- `Interrupt.fiberId`: `number | null`;
- `errorSchema`: `not: {}`.

There are four current `not` sites across the two identical stream extensions. `not: {}` is the
JSON Schema never/impossible shape, not an unrestricted value. Preserve that meaning; do not invent
a carrier value or repair it from Effect implementation source. Because `Fail.error` is required,
that meaning makes the entire `Fail` branch uninhabitable. The public variant-set consequence and
the runtime classification of a `Fail`-tagged frame are not sealed yet.

### Current wrong behavior

- `MediaTypeProjector` stores `x-effect-stream` as opaque JSON in `SpecResponse.EffectStreamJson`.
- `OperationPlanBinder.ReadFailureEventName` validates only `encoding` and `failureEvent`; it ignores
  `causeSchema` and `errorSchema`.
- `StreamPlan` carries only payload type, adapter type, and failure-event name.
- `StreamAdapterEmitter` emits payload `JsonTypeInfo` only.
- `Pipeline.ReadStreamPayload` throws `OpenCodeTransportException` with `frame.Data` interpolated as
  text; no typed cause is materialized or preserved.

### Required behavior

- Add red evidence for the exact pinned `causeSchema` before implementation.
- Admit only the typed-schema applicator semantics needed by this pin, especially exact handling of
  `not: {}` as never/impossible. Refuse unsupported `not` shapes at their exact pointer rather than
  pretending to implement general JSON Schema negation.
- Before bind/emission chooses a public cause shape, obtain a maintainer decision for the
  uninhabitable `Fail` branch: do not silently drop it, emit an impossible public variant, or route a
  `Fail`-tagged frame through the unknown carrier/protocol-failure path.
- Carry the cause contract through ingestion -> binding -> naming -> model/union planning -> registry
  -> emission -> System.Text.Json source generation -> compile.
- Extend the generated-to-hand-written stream seam so the adapter exposes source-generated metadata
  for the declared cause, not a reflection or raw-text fallback.
- Parse a failure-named frame with that metadata and preserve the typed cause on the thrown failure
  path. Malformed, null, or unmaterializable causes remain transport/protocol failures.
- Preserve Q98 framing: unnamed frames are payloads, the declared failure name is the only cause
  frame, and every other event name is refused.
- After the `Fail` decision, preserve ADR-0009 unknown-variant behavior for genuinely unrecognized
  tags. A schema-invalid known `Fail` tag must not become an unknown variant by accident.
- Keep reflection disabled and keep the selected `session.log` stream method free of per-call
  options.

The `Fail` branch outcome is a mandatory pre-emission maintainer decision. If the typed
exception/carrier shape or generated public type names are not mechanically derivable from current
canon, stop for those decisions too. Do not add operation-ID branches, hidden curation semantics, or
a second schema source to make the pin convenient.

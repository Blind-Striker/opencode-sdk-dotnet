## Step 1 — Ship the branch

1. **Multi-agent review (maintainer-triggered):** the maintainer runs `/code-review ultra`
   on this branch — it is user-invoked and billed, an agent cannot start it; the no-arg form
   bundles the local branch and needs no remote. Triage findings red-test-first; anything
   touching public API names goes back to the maintainer before changing the baseline.
2. **Push + PR to `master`** (push only on the maintainer's explicit ask). PR body: the M1
   story, the `DEMO.md` transcript, and the pin-vs-installed version skew note
   (`a6a712a` vs `opencode2` v0.0.0-next-17403 — deliberate snapshot policy).
3. **Watch first-contact CI.** This work has never seen the three-OS matrix. Known risk: the
   Windows-only net472 test leg renders the shared `PublicApi.verified.txt` from embedded
   (Polyfill-supplied) attributes — if it diverges, split the baseline per TFM or scrub the
   attribute rendering; do not weaken the baseline test. `App.net472.config` must never flow
   into the package when packaging is later enabled.

## Step 2 — Open M2 (first breadth batch)

Write the 1–2 page batch plan when the branch merges, not earlier (ROADMAP rule). The
standing proposal to put before the maintainer: **`v2.session.list` + `v2.message.list` +
`v2.session.get`** — it converts the demo's raw curl calls into SDK methods and pulls in the
real M2 machinery:

- Query-parameter binding (drops the M1 `no query` wall) including optional parameters
  (`limit`, `order`, `cursor`) and the deferred `location[...]` scoping decision.
- List payloads (`IReadOnlyList<T>`) and the `{cursor, data}` / `{data, hasMore}` envelopes;
  the cursor/paginator shape from the API design spec is a **public API review**.
- The `List*` verb rule joining `OperationNamePolicy` (collection GETs currently name as
  `Get*`).
- Consider a deliberate pin refresh at this boundary (M2 boundary is the sanctioned moment;
  drift lands as reviewable git diffs).

## Step 3 — Horizon (order revisited at each milestone boundary)

- **M3 streams:** SSE engine; `v2.session.log` (`after`/`follow`) semantics re-researched.
- **M4 launcher:** `OpenCodeServer.StartAsync` over `opencode2 serve`; discovery-file and
  `--stdio` leash are candidate mechanisms.
- **M5 full surface:** complete profile, exclusion fingerprints (ADR-0008), packaging
  unblocks.
- **M6 operational closure:** `refresh-spec`, Extensions DI (the sandbox grows its Generic
  Host root then), retry/telemetry/hooks.
- Standing chores: the manual analyzer-package bump routine (nothing warns when it lags);
  v2 GA watch (research doc 15's open items).

## Stop Conditions

Public-API taste decisions go to the maintainer as options with a recommendation. The Arc B
stop-condition list (binder needing raw OpenAPI, name-branching emitters, structural unions,
ownership ambiguity, TFM breakage, partial packs) carries into M2 unchanged.

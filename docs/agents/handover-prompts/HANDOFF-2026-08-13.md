The helper currently emits this shape:

```csharp
internal static class OptionalCollectionInput
{
    internal static T Normalize<T>(T? value, T empty, Func<T, T> copy)
        where T : class => value is null ? empty : copy(value);
}
```

Generated properties use the already initialized backing field as the empty value:

```csharp
public IReadOnlyDictionary<string, JsonElement> Metadata
{
    get;
    init => field = OptionalCollectionInput.Normalize(value, field, static input => ...);
} = ...;
```

This is intentional. System.Text.Json's source-generated record path may pass null through the
init path for an absent optional collection. The helper's input is honestly nullable, while the
public property stays non-null. With `RespectNullableAnnotations=true`, explicit wire null is
rejected before assignment. Do not add `[AllowNull]`: a probe showed it also admits explicit JSON
null, violating the pinned schema.

## Locked And Approved Arc B Decisions

### Generator boundary

This is an opencode-specific generator, not a universal OpenAPI generator. It may fail closed on
opencode dialect shapes outside the current selected capability. However, endpoint and client
names must not be hard-coded in emitters or operation-ID branches.

The intended flow is:

```text
SpecIR + curation
       -> Binder policy
       -> final Client/Operation/Envelope/Error plans
       -> dumb Roslyn emitters
```

Emitters must not know `v2.session.message`, `health`, `session`, or `SessionClient`. They render
final plan values. A synthetic operation with the same supported shape but different names must
bind and emit without a new production branch.

### Bound handle

`SessionsClient` is the collection facade. It will eventually carry collection operations such
as list/create and currently exposes `GetSessionClient`.

`SessionClient` is a bound handle containing only the shared pipeline and immutable session ID.
It caches no server state. Session-scoped operations exist only on this handle; there is no
duplicate flat overload.

OpenAPI cannot infer that `sessionID` should be partially applied. This is public API taste and
therefore curation. Update the modern `session` row to:

```json
{
  "placement": "client",
  "clientName": "Sessions",
  "handleName": "SessionClient",
  "handleParameter": "sessionID"
}
```

The Binder applies one general rule to any modern group declaring a handle. Legacy remains flat,
even if a legacy route contains `sessionID`.

### Identifier casing

Use ordinary PascalCase for all acronym tokens, regardless of length. Wire spelling remains in
`JsonPropertyName`. Brand spellings such as `OAuth` remain curated exceptions when reached.

### Collection nullability

Requiredness and nullability are independent. For an optional non-null collection:

| Wire | SDK result |
|---|---|
| Property absent | Immutable empty collection |
| Property present with collection/object | Immutable defensive copy |
| Property present as explicit null | `JsonException` |

Do not make the public property nullable merely because the deserializer's assignment path may
use null for absence.

### HTTP and endpoint policy

- Add `<Reference Include="System.Net.Http" />` conditionally for net472. Do not add the old
  `System.Net.Http` NuGet package. Add the same framework reference to the net472 test path only
  if test code directly needs it.
- Use `HttpClient.SendAsync(HttpRequestMessage, ResponseHeadersRead, CancellationToken)` as the
  only send primitive.
- URI constructors make their URI authoritative. Reject a conflicting non-null
  `OpenCodeClientOptions.Endpoint`.
- BYO `HttpClient` requires `options.Endpoint`.
- Never read or mutate `HttpClient.BaseAddress` or `DefaultRequestHeaders`.
- Accept only absolute HTTP(S) endpoint URIs without query or fragment; preserve a normalized
  endpoint path prefix when joining generated routes.
- Self-created `HttpClient` is owned and disposed. Injected `HttpClient` is never disposed.
- Disposing the root still marks every SDK wrapper unusable.

### Decoration

- Resolve password once at construction: explicit option, then
  `OPENCODE_SERVER_PASSWORD`, then no auth.
- Basic authentication uses user `opencode`.
- Per-call directory overrides client directory and is sent as `x-opencode-directory`.
- Every request carries `OpenCode.Sdk/<informational-version>` User-Agent.
- Decorate each request, never shared client headers.

The exact safe extraction/sanitization of the informational version still needs an internal
implementation decision and tests. Do not silently substitute assembly version without noting
the behavioral difference.

### Error channels

API errors throw by default. `OpenCodeRequestOptions.NoThrow` is the only switch and applies per
call. It suppresses API-status exceptions only; usage, disposal, cancellation, transport, and
protocol failures still throw.

`OpenCodeResponse` carries `Status`, `IsError`, typed `Error`, and nullable error-path `RawBody`.
Throwing API failures carry the same status/error/raw body on `OpenCodeApiException`.

Only a tag allowed by that operation's status map becomes its concrete generated error type. An
unknown tag, undeclared status, or known tag returned at the wrong status becomes
`UnknownOpenCodeError` with exact tag and raw `JsonElement`. Malformed non-2xx JSON yields a null
typed error while preserving exact raw body. Unexpected or malformed 2xx is a protocol failure
wrapped as `OpenCodeTransportException`. Every `OperationCanceledException` passes through.

## Selected Wire Contracts

### `v2.health.get`

| Fact | Value |
|---|---|
| Method/path | `GET /api/health` |
| Parameters/body | None |
| 200 | JSON `{ "healthy": true }`, classified `Bare` |
| 400 | `InvalidRequestError` |
| 401 | `UnauthorizedError` |
| Public owner/method | `OpenCodeClient.GetHealthAsync` |
| Response/payload | `HealthResponse.Healthy : bool` |

The success root is promoted under:

```text
op:v2.health.get#/responses/200/content/application~1json/schema
```

The pinned boolean is a one-value literal but intentionally emits `bool`, preserving a future
false value rather than rewriting it.

### `v2.session.message`

| Fact | Value |
|---|---|
| Method/path | `GET /api/session/{sessionID}/message/{messageID}` |
| Bound parameter | required path string `sessionID` |
| Method parameter | required path string `messageID` |
| Body/query | None |
| 200 | JSON `{ "data": SessionMessage }`, classified `Data` |
| 400 | `InvalidRequestError` |
| 401 | `UnauthorizedError` |
| 404 | `MessageNotFoundError` or `SessionNotFoundError` |
| Public owner/method | `SessionClient.GetMessageAsync(messageId, ...)` |
| Response/payload | `SessionMessageResponse.Message : SessionMessage` |

The response roots are:

```text
op:v2.session.message#/responses/200/content/application~1json/schema
op:v2.session.message#/responses/404/content/application~1json/schema
```

The raw 404 `anyOf` repeats `SessionNotFoundError`. Existing union normalization deduplicates it,
so the Binder must consume the semantic two-type set and must not re-read raw JSON to recover the
discarded duplicate.

Relevant pinned source locations are `spec/openapi.json:9780` and
`spec/openapi.json:11449`.

## Operation Binding Blueprint

The following is a recommended minimal shape, not committed code. Keep it consumed-only and
adjust names only when an emitter demonstrably needs a different field.

| Plan | Minimum consumed facts |
|---|---|
| `ClientPlan` | root property name, collection client type, optional handle type/factory, handle parameter |
| `OperationParameterPlan` | wire name, final C# name, `TypeReferencePlan`, handle-bound flag |
| `EnvelopePlan` | response type, success status/media, wire payload name, public payload name/type, docs |
| `ErrorVariantPlan` | wire tag and concrete generated type |
| `ErrorMapPlan` | status, media type, allowed error variants |
| `OperationPlan` | operation ID, owner type, method, HTTP method, route names/template, parameters, response/adapter, error maps, docs |

Expected final values include:

| Operation | Owner | Method | Response | Adapter |
|---|---|---|---|---|
| Health | `OpenCodeClient` | `GetHealthAsync` | `HealthResponse` | `HealthResponseAdapter` |
| Message | `SessionClient` | `GetMessageAsync` | `SessionMessageResponse` | `SessionMessageResponseAdapter` |

The public route member names are not yet mechanically represented. Settle them before emission
because `OpenCodeRoutes` enters the API baseline. A coherent reference shape is nested
`OpenCodeRoutes.Health.Get` and `OpenCodeRoutes.Sessions.GetMessage(sessionId, messageId)`.
Nested public route classes trigger CA1034; use the repository's narrow, commented arbitration
pattern rather than weakening the rule globally.

### Existing seam problem

`SchemaPlanBinder` currently resolves final schema names internally and keeps `TypePlanBinder` as
a private nested class. `SchemaBindingResult` discards the name map. Operation binding needs the
same final types for path parameters and response payloads without duplicating schema policy.

Recommended direction:

1. Resolve schema names once per `SpecBinder.Bind` invocation.
2. Pass the same resolved map to both schema and operation binding.
3. Extract the nested type binder into a named internal collaborator or narrowly expose a
   reusable type-resolution service.
4. Keep emitters entirely free of SpecIR and curation.

Do not solve this by letting an operation emitter inspect schemas or by matching operation IDs.

### Validation algorithm

For each selected operation, bind or report located errors for all of these facts:

1. Surface and placement: M1 supports modern ordinary operations; modern group curation chooses
   root, collection, or declared handle. Legacy placement stays flat.
2. Transport shape: GET, no body, no query, no SSE/WebSocket/wildcard, one 200 success, JSON
   response bodies.
3. Path integrity: every route token has exactly one required path parameter; M1 parameters
   resolve to non-null string.
4. Handle binding: a declared handle parameter is removed from the method signature and stored
   on the handle; remaining parameters stay on the generated method.
5. Success root: verify required properties and forbidden additional properties rather than
   trusting envelope classification alone.
6. Error map: direct refs become one allowed variant; response-root marked unions flatten to a
   deduplicated tag/type list; all concrete errors use the generated error hierarchy.
7. Naming: final owner, method, response, route, adapter, parameter, and payload names collide
   nowhere in the selected output.
8. Ordering: clients/names ordinal, statuses numeric, variants ordinal by tag, generated paths
   ordinal.

Add an operation/protocol binding error category rather than mislabeling route/status/media
failures as schema errors.

### Curation changes

Add `[JsonPropertyName("handleParameter")] public string? HandleParameter` to `GroupCuration`.
Update curation validation so:

- Root placement rejects client, handle, and handle-parameter fields.
- Client placement requires `clientName`.
- `handleName` and `handleParameter` are paired.
- The handle parameter names a required path parameter on at least one selected modern operation
  in that group.
- Modern group coverage is selection-scoped during staged generation.
- Curation-to-spec orphan checks remain global.
- Legacy operations do not require or consume modern group-handle curation.

Remove the current hard-coded `sessionID` detection from `CurationValidator`.

The agreed pipeline signature is:

```csharp
Task<TResponse> ExecuteAsync<TResponse>(
    HttpMethod method,
    string route,
    ResponseAdapter<TResponse> adapter,
    OpenCodeRequestOptions? options,
    CancellationToken cancellationToken)
    where TResponse : OpenCodeResponse;
```

A small implementation is to buffer the M1 JSON body in `Pipeline`, then invoke a synchronous
adapter that maps `(status, rawBody)` to a typed envelope. Pipeline applies default throw versus
`NoThrow` after adaptation. This keeps HTTP ownership/channel policy in one place and
operation-specific JSON/status rules in generated adapters.

Generated operation methods perform guards and one delegation only. `OperationMethodEmitter`
should return Roslyn method members consumed by `ClientEmitter`; do not emit partial operation
files, because file/type analyzers require one owner per client type.

The exception constructors need deliberate treatment under CA1032 before the first API baseline.
Do not weaken the analyzer globally. The protected mock constructors must produce an instructive
`InvalidOperationException` when an unoverridden member reaches an absent pipeline.

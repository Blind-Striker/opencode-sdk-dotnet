## Session Mechanics The Docs Don't Carry

- Dev loop: all six gates before every commit under `set -o pipefail` with an explicit
  ALL-GREEN marker; red-test-first; commit per green increment; push on the working
  branch authorized inside an agreed loop; decisions to the maintainer as plain text with
  options and a recommendation — never dialog widgets; engage their notes in prose
  before touching code.
- Regen ritual: emitters → `dotnet run --file tools/opencode-tool.cs -- generate` →
  review the committed diff → snapshots received→verified after review →
  `generate --verify` before commit.
- Review-queue issues carry a **Trigger** section and a milestone in the title; full
  finding text goes into the issue body so nothing lives only in transient scratchpads.
- Multi-TFM traps are recorded in agent memory; Sonar's test-project probe misses
  TUnit-only projects (arbitrate via csproj `NoWarn` + one-line slopwatch-ignore).
- The maintainer reads answers, not tool traffic; batch decisions, lead with the
  recommendation.
